## 🎯 필수 환경 변수

### 1. Google Cloud API 키 (`YOUTUBE_API_KEY`)
```bash
export YOUTUBE_API_KEY="AIzaSyDXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"  # 구글 AI Studio에서 발급받은 실제 키
```
- **구독 제한:** 기본 10,000 일일 쿼트 (프로젝트 설정에 따라 다름).
- **보안 주의:** `.gitignore` 에 `.env` 파일을 추가하여 버전 관리에서 제외해야 합니다.
- **발급 경로:** Google Cloud Console → API & Services → Credentials

### 2. 채널 ID (`CHANNEL_ID`)
```bash
export CHANNEL_ID="UCXXXXXXXXXXXXXXXXXXXXXXX"  # 유튜브 스튜디오 또는 채널 설정에서 가져온 문자열 ID
```
- **채널 ID 추출 방법:** `https://www.youtube.com/channel/UC...` URL 에서 `UC...` 부분을 복사하거나 YouTube 스튜디오 → 설정 → 일반 → 채널 정보에서 확인.

### 3. 인증 방식 (`AUTH_MODE`)
```bash
export AUTH_MODE="service_account"  # 또는 "oauth2_client" (개인용)
```
- **권장:** 서버 환경이나 자동화 스크립트는 `service_account` 사용이 안정적입니다.
- **OAuth2:** 개인 개발자 계정이거나, 사용자마다 다른 인증이 필요할 경우 사용합니다.

# YouTube Data API 환경 설정 및 기술 분석 가이드

## 📋 1. 개요
YouTube Data API 를 연동하기 위한 환경 변수 (`YOUTUBE_API_KEY`, `CHANNEL_ID`) 와 인증 방식, 그리고 잠재적 문제점을 분석한 문서입니다.

---

## 🔑 2. 필수 환경 변수

### `YOUTUBE_API_KEY` (Google Cloud API 키)
- **용도:** YouTube Data API v3 호출 시 인증 token 으로 사용됨.
- **구독 제한:** 기본 10,000 일일 쿼트 (프로젝트 설정에 따라 다름).
- **보안 주의:** `.gitignore` 에 `.env` 파일을 추가하여 버전 관리에서 제외해야 합니다.

### `CHANNEL_ID` (유튜브 채널 ID)
- **용도:** 특정 채널의 정보 조회, 영상 업로드 등에 사용됩니다.
- **채널 ID 추출 방법:** `https://www.youtube.com/channel/UC...` URL 에서 `UC...` 부분을 복사하거나 YouTube 스튜디오 → 설정 → 일반 → 채널 정보에서 확인.

### `AUTH_MODE` (인증 방식)
```bash
export AUTH_MODE="service_account"  # 또는 "oauth2_client" (개인용)
```
- **권장:** 서버 환경이나 자동화 스크립트는 `service_account` 사용이 안정적입니다.
- **OAuth2:** 개인 개발자 계정이거나, 사용자마다 다른 인증이 필요할 경우 사용합니다.

---

## ⚠️ 3. 잠재적 문제점 및 기술 요구사항 분석

### 3.1 API 키 저장 및 보호 (보안)
- **문제:** `.env` 파일에 실제 키를 저장하면 소스 코드 공유 시 누출 위험.
- **해결:** `dotenv` 라이브러리로 로딩하고, CI/CD 파이프라인에서 키를 주입하거나 GCP Secret Manager 를 사용하는 것을 권장합니다.

### 3.2 채널 ID 자동 추출 (편의성)
- **문제:** 채널 ID 를 수동으로 입력하는 것은 실수 발생 위험이 큽니다.
- **해결:** YouTube Data API 가 제공하는 `channels.list` 엔드포인트를 사용하여 채널 제목이나 썸네일을 기준으로 자동으로 채널을 찾을 수 있습니다.

### 3.3 쿼트 제한 및 리셋 (성능)
- **문제:** 일일 쿼트 초과 시 API 호출 실패.
- **해결:** 백엔드에서 `YOUTUBE_API_KEY` 와 `CHANNEL_ID` 를 조합하여 REST API 를 호출하고, 응답의 `quotaRemaining` 값을 체크하여 다음 요청을 계획합니다.

### 3.4 다중 채널 지원 (확장성)
- **문제:** 하나의 API 키로 여러 채널을 관리할 수 있지만, 혼동 가능성이 있습니다.
- **해결:** `.env` 에 `CHANNEL_IDS="UC..., UC..."` 형식으로 다중 채널 ID 를 저장하거나, 코드에서 채널 목록을 동적으로 로드합니다.

# 🎯 KPI 자동화 파이프라인 초기 지표 정의 (v1)

## 1. 배경 및 목적
공인중개사 대상 AI 기반 가격 효율성 지수 SaaS 모델의 **초기 지표(KPI)** 를 정의하여, MVP 검증과 수익화 전략 수립에 필요한 기준을 마련합니다. 데이터 접근 환경 구축 완료 후, 확보된 데이터(예: 유튜브 트렌드, 공인중개사 행동 패턴 등)를 기반으로 KPI 자동화 파이프라인 구동을 위한 초기 지표를 재검토하고, 다음 단계의 전략적 목표를 설정합니다.

## 2. 핵심 지표 (KPI) 정의

### 2.1 주요 비즈니스 지표
| 지표명 | 공식/계산 방법 | 목표값 (3개월) | 데이터 출처 |
|--------|----------------|----------------|-------------|
| **유입 트래픽** | `유저수 / 월간 신규 가입자` | 5,000 명 → 10,000 명 | Google Analytics, 앱 스토어 |
| **활성도 (DAU/MAU)** | `월간 일일 활성 사용자 수 / 월간 전체 사용자` | 30% 이상 | 서버 로그, DB |
| **매출 전환율** | `(프로 구독자 수 × ARPU) / 총 유입 트래픽` | 15% → 25% | 결제 게이트웨이 (PayPal/Stripe) |
| **평균 수익성 (ARPU)** | `총 매출 / 총 유료 사용자` | $5 → $8 | 결제 시스템 |
| **고객 생애 가치 (LTV)** | `(ARPU × 평균 구독 기간) - 고객 획득 비용(CAC)` | LTV > 3×CAC | CRM 데이터 |
| **사용자 이탈률** | `(월간 신규 가입자 - 월간 활성 사용자) / 월간 신규 가입자` | <10% | 서버 로그, DB |

|--------|-----------|-----------|-----------|-------------------|
| **Basic** | 신규 중개사 | AI 매물 분석(기본), 가격 효율성 지수(월 1 회) | $5/월 | LTV > 2.5×CAC |
| **Pro** | 성장형 중개사 | 실시간 시장 트렌드, 블로그 자동작성, KPI 대시보드 | $15/월 | LTV > 3×CAC |
| **VIP** | 대형 사무소 | 맞춤형 AI 상담원(텔레그램), 재개발 투자 시뮬레이션, 우선 고객 지원 | $30/월 | LTV > 4×CAC |

### 2.3 기술 지표 (KPI 자동화 파이프라인)
| 지표명 | 목표치 | 데이터 출처 |

### 1. `src/types.ts` (PropertyListing 타입 추가)
```typescript
// 기존 PropertyListing 정의 유지
interface PropertyListing {
  // ... 주소, 용도, 사진 URL 등
  aiGeneratedBlogPost?: string;     // AI 가 생성한 블로그 글
  complianceStatus: 'green' | 'yellow' | 'red'; // 필수 표기 확인 결과
}

// MVP 전용 추가 필드 (점수 계산용)
interface EfficiencyData {
  inputTimeSeconds: number;         // 사용자 입력 소요 시간 (클라이언트 측 타이머에서 전송)
  aiResponseTokens: number;         // AI 응답 길이 (단어 수) → 정확도 대리 변수로 사용
  renderPngSizeKB: number;          // 생성된 PNG 파일 크기 (저장 효율성 지표)
}

export interface PropertyListingWithScore extends PropertyListing {
  efficiencyScore?: number;         // 최종 가격 효율성 지수 (0~100, 3 자리 소수점)
  metadata: EfficiencyData;
}
```

### 2. `lib/efficiencyUtils.ts` (지수 계산 로직 - MVP 기본판)
```typescript
// 파일 생성 후 server.ts 에 import
import { PropertyListingWithScore } from '../src/types';

const calculateEfficiencyScore = (listing: PropertyListing): number => {
  const inputTime = listing.metadata.inputTimeSeconds || 0;
  const aiTokens = listing.metadata.aiResponseTokens || 1000; // 기본값 (AI 응답 길이)
  const renderSize = listing.metadata.renderPngSizeKB || 500;

  // MVP 로직: 입력 시간 단축 + AI 생성 품질(토큰 수) + 저장 효율성(파일 크기) 가중치 합산
  const baseScore = Math.min(100, 100 - (inputTime / 60)); // 1 분당 점수 1 감소
  const aiQualityScore = Math.max(0, Math.min(30, (aiTokens / 50) * 0.01)); // 토큰 수에 비례
  const renderEfficiencyScore = Math.max(0, 40 - (renderSize / 2000)); // 2MB 당 점수 0.2 감소

  return baseScore + aiQualityScore + renderEfficiencyScore;
};
```

### 3. `server.ts` (엔드포인트 확장)
- **기존 엔드포인트**: `POST /api/generate-listing`, `POST /api/generate-blog`
- **MVP 추가 로직**: 두 엔드포인트 모두에서 `responseSchema` 에 `efficiencyScore` 필드를 포함하여 반환.

```typescript
// server.ts (요청 본문 예시)
app.post('/api/generate-listing', async (req, res) => {
  // 1. Gemini AI 호출 → PropertyListing 생성
  const listing = await gemini.generate(req.body);
  
  // 2. 효율성 점수 계산 (클라이언트에서 전송한 inputTimeSeconds 활용)
  const efficiencyData: EfficiencyData = req.body; // 클라이언트 측 타이머 값 포함
  const score = calculateEfficiencyScore({ ...listing, metadata: { ...efficiencyData } });

  // 3. 응답 JSON 구조 (기존 필드 + 새 필드)
  res.json({ success: true, data: listing, efficiencyScore: score.toFixed(2) });
});
```
