## 2. 파일 경로 오류 처리 및 디렉토리 전략
**문제:** 절대 경로 추측, 상대 경로 혼용, 디렉토리 생성 실패로 인한 `FileNotFoundError`  
**해결:** 항상 **절대 경로**를 사용하고, 디렉토리는 스크립트 실행 전과 후 모두 검증하는 로직을 적용합니다.

### 2.1 절대 경로 사용 규칙 (최우선)
- ✅ `os.path.abspath()` 또는 `pathlib.Path.resolve()` 를 사용하여 모든 파일 읽기/쓰기를 수행합니다.
- ✅ 환경 변수 (`HOME`, `USERPROFILE`) 나 사용자 입력 없이도, **현재 스크립트 실행 위치**를 기준으로 절대 경로를 자동 생성합니다.
  ```python
  from pathlib import Path
  
  SCRIPT_DIR = Path(__file__).resolve().parent
  DATA_ROOT = Script_dir.parent / "data_collector"  # 예: Scripts/ -> 데이터/
  OUTPUT_FOLDER = Data_root / "{region}/{property_type}/{date}"
  OUTPUT_FOLDER.mkdir(parents=True, exist_ok=True)
  ```

### 2.2 디렉토리 생성 전략
- ✅ `mkdir(parents=True, exist_ok=True)` 를 사용하여 모든 상위 디렉토리가 없어도 자동으로 생성하고, 중복 시 오류를 방지합니다.
- ✅ **디렉토리 존재 여부**와 **권한 문제**를 감지하여 로그에 기록하는 로직을 추가합니다:
  ```python
  try:
      output_folder.mkdir(parents=True, exist_ok=True)
  except PermissionError as e:
      log.error(f"디렉토리 생성 권한 오류: {e}. 저장소 경로 변경 필요.")
      sys.exit(1)
  except OSError as e:
      log.error(f"디렉토리 생성 시스템 오류: {e}")
      sys.exit(1)
  ```

### 2.3 저장 규칙 `{region}/{property_type}/{date}.json` 적용
- ✅ `region`, `property_type`, `date` 값을 스크립트 실행 전 미리 정의된 상수로 설정하고, **입력 데이터의 유효성**을 검증합니다:
  ```python
  VALID_REGIONS = ['서울', '경기']
  VALID_PROPERTY_TYPES = {'아파트': 'apartment', '오피스텔': 'office'}

  def validate_input(region: str, prop_type: str) -> Tuple[str, str]:
      if region not in VALID_REGIONS:
          raise ValueError(f"유효하지 않은 지역: {region}")
      property_key = prop_type.replace(' ', '').strip()
      if property_key not in VALID_PROPERTY_TYPES:
          raise ValueError(f"유효한 프로퍼티 타입 없음: {prop_type}")
      return VALID_REGIONS[VALID_REGIONS.index(region)], VALID_PROPERTY_TYPES[property_key]
  ```

## 3. 선택자 (Selector) 파싱 및 불일치 처리
**문제:** 웹사이트 구조 변경으로 기존 선택자가 작동하지 않거나, 동적 렌더링 콘텐츠가 지연되어 `ElementNotFound` 발생  
**해결:** 선택자를 **테스트 데이터셋**을 기반으로 자동 검증하고, 대체 로직을 포함한 로버스트 파서를 구현합니다.

### 3.1 선택자 검증 프로세스
- ✅ 스크립트 실행 전, 테스트 브라우저로 페이지를 로드하고 선택자의 존재 여부를 **자동으로 확인**하는 함수를 작성합니다:
  ```python
  from selenium.webdriver.common.by import By
  
  def check_selector(driver, selector):
      try:
          elements = driver.find_elements(By.CSS_SELECTOR, selector)
          if not elements:
              raise Exception(f"선택자 `{selector}`에서 요소가 하나도 없습니다.")
          return True
      except Exception as e:
          print(f"선택자 검증 실패: {e}")
          return False
  ```

### 3.2 대체 로직 및 Fallback
- ✅ 선택자가 작동하지 않을 경우, **대체 CSS 선택자**나 **XPath**를 순차적으로 시도합니다:
  ```python
  SELECTORS = [
      "div.property-card",          # 기본
      "article[data-type='property']",  # 대체 1
      ".item-list__item"           # 대체 2
  ]
  
  def find_element_fallback(driver, *selectors):
      for sel in selectors:
          try:
              return driver.find_element(By.CSS_SELECTOR, sel)
          except Exception:
              continue
      raise Exception("모든 선택자가 실패했습니다.")
  ```

### 3.3 동적 콘텐츠 지연 처리 (Explicit Waits)
- ✅ 페이지 로드 후 **선택자가 나타날 때까지 대기**하는 로직을 적용합니다:
  ```python
  from selenium.webdriver.support.ui import WebDriverWait
  from selenium.webdriver.support import expected_conditions as EC
  
  def wait_for_element(driver, selector, timeout=10):
      try:
          return WebDriverWait(driver, timeout).until(
              EC.presence_of_element_located((By.CSS_SELECTOR, selector))
          )
      except TimeoutException:
          print(f"선택자 `{selector}`를 {timeout} 초 동안 찾을 수 없었습니다.")
  ```

## 4. 네트워크 및 시간 오류 처리
**문제:** 서버 응답 지연, DNS 오류, 시계 차이로 인한 데이터 불일치  
**해결:** 타임아웃 설정, 재시도 로직, 로깅을 체계적으로 적용합니다.

### 4.1 요청 타임아웃 및 재시도
- ✅ 모든 HTTP 요청에 **5 초 타임아웃**을 설정하고, 실패 시 최대 3 회까지 자동 재시도합니다:
  ```python
  import requests
  
  def fetch_with_retry(url, timeout=5, retries=3):
      for attempt in range(retries):
          try:
              response = requests.get(url, timeout=timeout)
              if response.status_code == 200:
                  return response.text
              else:
                  print(f"HTTP 에러 코드: {response.status_code}")
          except requests.exceptions.Timeout:
              continue
          except Exception as e:
              print(f"요청 실패: {e}")
      raise ConnectionError("최대 재시도 횟수 초과")
  ```

### 4.2 시계 동기화 로직 (Optional)
- ✅ 서버와 클라이언트의 **시간 차이**가 크지 않은지 확인하고, 차이가 5 초를 초과하면 로그에 경고합니다:
  ```python
  import datetime
  
  def check_time_sync(server_time_str):
      try:
          server_dt = datetime.datetime.fromisoformat(server_time_str.replace('Z', '+00:00'))
          local_dt = datetime.datetime.now(datetime.timezone.utc)
          diff = abs((server_dt - local_dt).total_seconds())
          if diff > 300:
              print(f"⚠️ 시계 차이 경고: {diff} 초")
      except Exception:
          pass  # 파싱 실패 무시
  ```

## 5. 예외 처리 및 로깅 구조
**문제:** 스크립트 중단 없이 중요한 오류만 감지하고, 데이터 수집을 계속할 수 있는 **부분 실행 (Partial Run)** 로직  
**해결:** `try-except` 블록을 전략적으로 배치하고, **오류 상태에서도 다른 데이터 소스로 전환**하는 구조를 만듭니다.

### 5.1 예외 분류 및 대응
- ✅ 주요 오류 유형별로 **다른 처리 경로**를 정의합니다:
  ```python
  class DataCollectorError(Exception): pass
  
  def process_with_fallback():
      try:
          data = scrape_main_source()
      except DataCollectorError as e:
          log.warning(f"주요 소스 실패: {e}. 대안 소스 전환.")
          return scrape_alternative_source()
  ```

### 5.2 로깅 수준 및 파일
- ✅ `logging` 모듈을 사용하여 **DEBUG**, `INFO`, `WARNING`, `ERROR` 레벨로 상세한 로그를 기록합니다:
  ```python
  import logging
  
  logger = logging.getLogger(__name__)
  
  try:
      # 수집 로직...
      pass
  except Exception as e:
      logger.error(f"예상치 못한 오류 발생: {e}", exc_info=True)
  ```

### 5.3 데이터 복구 및 부분 저장
- ✅ 한 번의 실행에서 일부 데이터만 수집되더라도, **이미 성공적으로 파싱된 데이터를 즉시 JSON 파일에 저장**합니다:
  ```python
  def save_partial_data(data_list, output_path):
      import json
  
      if data_list:
          with open(output_path, 'w', encoding='utf-8') as f:
              json.dump(data_list, f, ensure_ascii=False, indent=2)
          logger.info(f"부분 데이터 {len(data_list)} 건 저장 완료: {output_path}")
  ```

## Day 1: [시작] "감정가만 믿다가 손실한 당신의 경쟁자들"

- **주제:** 왜 감정가는 이제 안 통하는가? (시장 데이터와 AI 기반 가격 효율성 지수의 등장)
- **핵심 메시지:** 감정가는 과거의 경험에 의존하지만, 현재 시장은 실시간 데이터 흐름으로 움직인다. 당신의 경쟁자들은 이미 데이터를 활용하고 있다.
- **스크립트 방향:**
  - **후크:** "당신의 가장 큰 라이벌이 바로 당신의 감정가 산정 방식입니다." (화면: 감정가 표 vs 실시간 거래 데이터 차트)
  - **본문:** 감정가의 한계 사례 (예: 작년 가격과 올해 실제 거래 가격의 괴리), 데이터 기반 의사결정의 중요성 소개.
- **초기 제작 방향:**
  - **비주얼:** 강렬한 숫자 대비 효과, 경쟁사 vs 자사의 데이터 활용도 비교 차트.
  - **디자인 요구사항:** Day별 썸네일 및 광고 배너용 비주얼 리스트 추가 (Designer 에게 분배).

## Day 2: [이해] "AI 기반 가격 효율성 지수란 무엇인가?"

- **주제:** 복잡한 수식을 모르는 당신도 이해할 수 있는 '가격 효율성 지수'의 기본 원리.
- **핵심 메시지:** 이 지수는 시장 거래 데이터, 지역별 공급/수요 비율, 정책 변화 등을 종합하여 현재 가격의 공정한 범위를 제시한다. 당신의 가격을 여기에 맞춰야 한다.
- **스크립트 방향:**
  - **후크:** "당신의 가격이 이 지수보다 15% 높다면, 실제 시장에서는 '고평가'로 인식됩니다." (화면: 지수 바와 가격 바의 차이)
  - **본문:** 간단한 예시 (A 지역 매매 평균 가격 vs B 지역), 지수의 구성 요소 설명.
- **초기 제작 방향:**
  - **비주얼:** 숫자 애니메이션, 지수를 시각적으로 표현하는 그래프.
  - **디자인 요구사항:** 복잡한 수식을 단순화한 인포그래픽 제작 요청.

## Day 3: [사례] "이 공인중개사의 성공 비법" (Case Study)

- **주제:** 데이터 기반 가격 산정을 적용하여 1 달 만에 거래 건수를 2 배 늘린 실제 사례.
- **핵심 메시지:** 이론만 알면 안 된다. 이 방법론을 따라 했을 때 실제로 어떤 결과가 발생하는지 보여준다. 당신의 채널도 이런 결과를 기대할 수 있다.
- **스크립트 방향:**
  - **후크:** "저의 고객 중 한 분, 그는 감정가를 20% 낮추고 거래를 완료했습니다." (화면: 전/후 비교 사진)
  - **본문:** 사례 배경 (지역, property 타입), 적용한 데이터 분석 단계, 결과.
- **초기 제작 방향:**
  - **비주얼:** 인포그래픽 스타일의 타임라인, 고객 인터뷰 영상 클립 (가상).
  - **디자인 요구사항:** 실제 거래 내역을 기반으로 한 '결과물' 이미지 생성 (Designer 분배).

## Day 4: [적용] "당신의 지역에 맞는 데이터 분석법"

- **주제:** 전국 평균이 아닌, 당신의 지역(구) 단위에서 어떻게 데이터를 접근할 것인가?
- **핵심 메시지:** 서울 강남과 인천 송산의 데이터는 완전히 다릅니다. 지역별 특성에 맞춘 데이터 수집 및 활용 전략을 소개합니다.
- **스크립트 방향:**
  - **후크:** "당신의 지역은 '강남'이 아닙니다. 당신의 지역에 맞는 데이터가 있습니다." (화면: 지도 기반 데이터 시각화)
  - **본문:** 주요 도시별 데이터 특징, 공인중개사들이 직접 사용할 수 있는 무료/유료 데이터 출처 소개.
- **초기 제작 방향:**
  - **비주얼:** 지역별 데이터 열도, 무료 API 및 보고서 링크 리스트.
  - **디자인 요구사항:** '지역별 데이터 출처' 인포그래픽 제작 (Designer 분배).

## Day 5: [오해] "데이터를 쓰면 고객 신뢰가 떨어진다" – 거짓말인가?

- **주제:** 데이터를 활용하면 오히려 신뢰도가 올라가는 이유.
- **핵심 메시지:** '감정'으로 가격을 맞추는 것이 아니라, 객관적 데이터를 바탕으로 가격을 제시하는 것이 진정한 전문가의 모습입니다.
- **스크립트 방향:**
  - **후크:** "고객이 당신에게 더 많이 물어보는 것은 당신이 '전문가'라는 이유 때문입니다." (화면: 고객 질문 vs 데이터 기반 답변 비교)
  - **본문:** 고객 신뢰도 조사 결과, 데이터 활용 시 대화 흐름 변화.
- **초기 제작 방향:**
  - **비주얼:** 신뢰도 그래프, 전문가 인터뷰 클립 (가상).
  - **디자인 요구사항:** 신뢰도에 대한 인포그래픽 제작.

## Day 6: [실전] "오늘 바로 적용할 체크리스트"

- **주제:** 오늘 영상 내용을 바탕으로 즉시 사용할 수 있는 공인중개사 '데이터 활용 체크리스트'.
- **핵심 메시지:** 이론을 끝으로 두지 마세요. 이 체크리스트를 오늘 저녁에 완성하세요. 내일 아침부터 다른 방식의 거래가 시작됩니다.
- **스크립트 방향:**
  - **후크:** "당신의 채널이 성공하려면, 오늘 밤 10 시까지 이 체크리스트를 완료하세요." (화면: 체크리스트 스크린샷)
  - **본문:** 체크리스트 항목별 설명 (예: '지역 데이터 수집 시작하기', '가격 효율성 지수 계산하기').
- **초기 제작 방향:**
  - **비주얼:** 체크리스트 PDF 나 이미지로 변환 가능한 자료.
  - **디자인 요구사항:** 실제 사용할 수 있는 PDF 파일 생성 및 공유 링크 포함.

## Day 7: [행동] "결제 전환을 위한 최종 CTA"

- **주제:** 공인중개사 '결제 100 건' 목표를 달성하는 데 필요한 다음 단계.
- **핵심 메시지:** 이 콘텐츠 시리즈는 당신의 채널을 성장시키는 데만 도움이 되지 않습니다. 직접적인 결제 전환(예: 유료 데이터 구독, 컨설팅) 으로 이어지는 것을 보여줍니다.
- **스크립트 방향:**
  - **후크:** "당신의 채널이 성공하려면, 오늘 밤 10 시까지 이 체크리스트를 완료하세요." (화면: 체크리스트 스크린샷)
  - **본문:** 결제 전환을 위한 방법 소개 (예: 데이터 구독 패키지), 다음 콘텐츠 예고.
- **초기 제작 방향:**
  - **비주얼:** 결제 페이지 디자인, 구독 패키지 인포그래픽.
  - **디자인 요구사항:** 결제 페이지 및 구독 패키지 비주얼 제작 (Designer 분배).
