### 🔍 데이터 확보 리스크 분석 (Risk Analysis)

현재 목표 달성 과정에서 발생할 수 있는 주요 기술적 리스크는 다음과 같습니다. 이는 데이터 안정화가 완료되기 전까지 잠재적으로 존재하며, Phase 2 실행 시 치명적인 오류를 유발할 수 있습니다.

1.  **데이터 무결성 리스크 (Data Integrity Risk):**
    *   **문제:** 네이버 부동산/MLS 데이터 파싱 및 레이블링 과정에서 발생하는 노이즈나 누락 데이터가 최종 KPI 측정에 오차를 발생시킬 수 있습니다. 특히 AI 가치 평가 모델 학습에 사용되는 데이터의 품질(Price\_Efficiency\_Label)이 불안정할 경우, 최적화된 가격 전략 적용이 잘못된 결정을 유도합니다.
    *   **영향:** 목표 달성 성공률 하락 및 비효율적인 마케팅 집행.

2.  **파이프라인 안정성 리스크 (Pipeline Stability Risk):**
    *   **문제:** 데이터 수집(`api_collector.py` 등)부터 최종 저장(`cleaned_market_data.parquet`)까지의 End-to-End 무결성이 보장되지 않을 경우, 실시간 또는 배치 업데이트 시점에 데이터 불일치(Staleness)가 발생하여 결제 시스템과의 연동 오류를 초래할 수 있습니다.
    *   **영향:** 실제 결제 흐름에서 데이터 기반 의사결정 실패.

3.  **Fail-Fast 메커니즘 리스크 (Failure Mechanism Risk):**
    *   **문제:** LLM 실패 방지 메커니즘(FTRC 연동)이 예기치 않은 입력이나 모델 오류에 대해 적절히 작동하지 않을 경우, 시스템은 잘못된 데이터를 기반으로 다음 단계로 진행하게 되어 전체 파이프라인이 멈추거나 오염될 수 있습니다.
    *   **영향:** 데이터 안정화 과정 중 예상치 못한 다운타임 및 재작업 발생.

### 🛠️ Phase 2 실행을 위한 기술적 선행 작업 (Prerequisites for Phase 2 Execution)

위 리스크를 최소화하고 Phase 2의 성공적인 실행을 보장하기 위해, 데이터 안정화 완료 시점까지 다음 세 가지 영역에 대한 **기술적 선행 작업**을 즉시 착수해야 합니다.

#### 1. 측정 인프라 강화: 실시간 무결성 검증 시스템 구축 (Measurement Infrastructure Hardening)

*   **목표:** 모든 데이터 흐름의 체크포인트 로깅 및 Fail-Fast 전략의 완벽한 작동 보장.
*   **구체적 작업:**
    *   `data_pipeline.py` 내에 **트랜잭션별 체크포인트 로깅 함수**를 재검토하고, 각 단계(수집 $\rightarrow$ 파싱 $\rightarrow$ 레이블링 $\rightarrow$ 저장) 완료 시점에 대한 메타데이터(Timestamp, Source Hash)를 불변적으로 기록하도록 보강해야 합니다.
    *   FTRC 연동 지점에서 **Input/Output 검증 모듈**을 추가하여, LLM 실패가 데이터 파이프라인에 미치는 영향을 실시간으로 측정하고 경고하는 로직을 통합합니다.

#### 2. 데이터 정제 자동화: 레이블링 품질 보장 강화 (Labeling Quality Assurance)

*   **목표:** AI 가치 평가 모델 학습의 핵심인 `Price_Efficiency_Label`의 신뢰도 극대화.
*   **구체적 작업:**
    *   기존에 구현된 **자동 레이블링 파이프라인**에 대해, **다중 검증 루프(Multi-Verification Loop)**를 도입합니다. 즉, 자동 생성된 레이블 외에, 특정 임계치(예: 가격 대비 면적 비율)를 벗어나는 데이터 샘플을 자동으로 플래그 지정하고, 이를 수동 검토 대기열로 분리하는 프로세스를 추가해야 합니다.
    *   데이터 파이프라인에서 발생하는 이상치(Outlier)에 대한 **자동 통계적 경고 시스템**을 구현하여, 레이블링 오류가 발생한 데이터를 즉시 격리하도록 설정합니다.

#### 3. 결제 연동 안정화: 최종 KPI 측정 기준의 자동화 (Payment Flow Automation)

*   **목표:** 데이터 확보 시점과 무관하게 예측 가능한 KPI 측정을 위한 시스템 준비.
*   **구체적 작업:**
    *   Phase 2-3에서 필요한 **사용자 인지 부하 최소화 모듈(Designer 산출물)**이 실제 결제 퍼널에 통합될 때, 데이터 로깅이 실시간으로 이루어지도록 API 인터페이스를 점검합니다.
    *   결제 전환율 계산 시, 데이터 수집 지연 시간($\Delta t$)을 변수로 포함하여 **시간 기반의 보정 계수**를 적용하는 로직을 설계에 반영해야 합니다. 이는 데이터 안정화가 완료되지 않았더라도 최소한의 예측치를 제공하기 위함입니다.
