# 🚀 Co_Dari API Spec v3.0 — KPI 기반 피드백 루프 및 자동화 파이프라인

## 1. API 명세 개요
- **버전**: 3.0
- **목적**: 공인중개사 대상 메시지 발송 빈도 조절, A/B 테스트 환경 구축, 동적 노출 빈도 제어 로직 구현
- **주요 엔드포인트**:
  - `POST /api/v1/message/send` — 메시지가 발송될 때 KPI(응답률, 만족도)를 실시간으로 수집하고 다음 발송 빈도를 계산하는 로직 포함.
  - `GET /api/v1/ab-test/results` — A/B 테스트 결과를 실시간으로 조회하여 최적의 노출 빈도를 도출하는 엔드포인트.
  - `POST /api/v1/feedback/close-loop` — 클로즈드 루프 피드백 데이터(사용자 응답, 만족도)를 저장하고 다음 발송 로직에 적용.

## 2. KPI 기반 메시지 발송 빈도 조절 로직 (동적 노출 빈도 제어)
### 목표:
- 응답률 유지 및 만족도 향상 동시 최적화.
- 응답률이 7/10 이하일 경우 노출 빈도를 20% 증가시키고, 만족도가 4.0/5 이하인 데이터는 실시간으로 모니터링하여 개선 요청을 전달.

### 단계별 로직:
1. **초기 발송 (Day 0)**:  
   - 기본 노출 빈도 = 1 회/일 (사용자 경험 최적화).  
   - A/B 테스트 시작: 그룹 A(기본) vs 그룹 B(동적 증가).  

2. **피드백 수집 (T+1 ~ T+7)**:  
   - `POST /api/v1/message/send` 호출 시 사용자 응답 데이터(응답률, 만족도)를 DB에 저장.  
   - 실시간 분석 엔진에서 다음 발송 빈도를 계산.  

3. **동적 노출 빈도 증가 (Day 8 이후)**:  
   - 만약 그룹 A의 평균 응답률이 7/10 이하라면, 다음 발송 빈도를 20% 증가시켜야 함.  
   - 만족도가 4.0/5 이하인 데이터는 `POST /api/v1/feedback/close-loop` 로 저장하고, 개발팀에 개선 요청 전달.  

4. **최적화 루프 (Day 15 이후)**:  
   - A/B 테스트 결과를 `GET /api/v1/ab-test/results`로 조회하여 최적의 노출 빈도를 도출.  
   - 그룹 B가 더 높은 응답률과 만족도라면, 기본 로직을 그룹 B의 빈도로 변경.  

## 3. A/B 테스트 환경 구축 계획
### 목표:
- 메시지 발송 빈도와 사용자 반응 간의 상관관계 분석 및 최적화.

### 단계별 실행 계획:
1. **테스트 설계**:  
   - 그룹 A(기본) vs 그룹 B(동적 증가).  
   - 각 그룹에 최소 10,000 명의 사용자가 포함되도록 분배.  

2. **데이터 수집 및 분석**:  
   - `POST /api/v1/message/send` 호출 시 사용자 응답 데이터를 실시간으로 수집.  
   - A/B 테스트 결과를 `GET /api/v1/ab-test/results`로 조회하여 최적의 노출 빈도를 도출.  

3. **최적화 결정**:  
   - 그룹 B가 더 높은 응답률과 만족도라면, 기본 로직을 그룹 B의 빈도로 변경.  

## 4. 기술적 병목 지점 및 해결 방안
### 병목 지점:
- 실시간 피드백 수집 시 DB 연결 지연 (특히 고부하 환경).  
- A/B 테스트 데이터 분석 시 CPU 과부하 (대규모 데이터 처리).

### 해결 방안:
1. **DB 최적화**:  
   - Redis 캐시 활용하여 실시간 피드백 데이터를 저장.  
   - PostgreSQL 클러스터링을 통해 부하 분산.  

2. **데이터 분석 최적화**:  
   - Apache Spark 또는 Flink 를 활용한 스트리밍 데이터 처리.  
   - GPU 가속된 머신러닝 모델 적용 (예: TensorFlow Serving).

## 5. API 연동 방안 및 테스트 환경 구축
### 연동 방안:
- `POST /api/v1/message/send` 호출 시 사용자 응답 데이터를 실시간으로 수집하고, 다음 발송 빈도를 계산하는 로직 포함.  
- `GET /api/v1/ab-test/results` 엔드포인트를 통해 A/B 테스트 결과를 조회하여 최적의 노출 빈도를 도출.  

### 테스트 환경 구축:
1. **테스트 서버**:  
   - AWS EC2 인스턴스 (t3.medium) 2 대 준비.  
   - Docker 컨테이너를 활용하여 API 서버 실행.  

2. **데이터 수집 및 분석 파이프라인**:  
   - Kafka 를 활용한 실시간 데이터 스트리밍.  
   - Elasticsearch 를 활용한 로그 분석 및 시각화 (Kibana).  

3. **모의 테스트**:  
   - 고부하 환경에서 API 응답 시간, 데이터 처리 속도 등을 측정하여 병목 지점 확인.

## 6. 비즈니스 로직 확정

- 최적화 루프 주기: 15 일마다 한 번씩 A/B 테스트 결과를 분석하여 기본 로직 변경.

### 단계별 비즈니스 로직:
1. **초기 발송**:  
   - 기본 노출 빈도 = 1 회/일 (사용자 경험 최적화).  

2. **피드백 수집 및 동적 증가**:  
   - 응답률이 7/10 이하일 경우, 다음 발송 빈도를 20% 증가시키고, 만족도가 4.0/5 이하인 데이터는 실시간으로 모니터링하여 개선 요청 전달.  

3. **최적화 루프**:
