# 💼 KPI 자동화 파이프라인: 필수 측정 지표 (Metrics) 및 비즈니스 로직 초안

## 1. 필수 측정 지표 (Metrics) 정의

KPI 자동화 파이프라인이 공인중개사의 수익성 ('결제 100건' 목표) 과 업무 효율을 동시에 측정하기 위해, 다음 4 가지 핵심 지표를 모니터링합니다. 각 지표는 '자동화된 데이터 수집 → 실시간 분석 → 행동 유도' 사이클의 입력값이 됩니다.

| **지표명** | **계산식/정의** | **목표치 (예시)** | **측정 주기** | **주요 연동 기능** |
|-----------|------------------|-------------------|---------------|--------------------|
| **거래 건당 평균 수익성 (Gross Profit per Deal, GPPD)** | `(수익 - 자동화된 비용 (수수료, 세금, 마케팅)) / 거래 건` | 목표: 1 건당 +30 만 원 이상 | 일일/실시간 | 가격 전략 모듈 연동, ROI 분석 |
| **자동화 처리 시간 (Automation Latency)** | `데이터 수집부터 행동 유도까지 소요된 시간` | 목표: 5 분 이내 | 실시간 | 데이터 파이프라인 최적화 |
| **고객 응대 효율성 (Response Efficiency Score)** | `(automated 응답 건수 / 총 요청 건수) * 응답 만족도 점수` | 목표: 자동응답율 80% 이상, 만족도 4.3/5 | 일별 | AI 채팅봇 연동, CRM 분석 |
| **시장 기회 포착율 (Market Opportunity Capture Rate)** | `자동화된 시장 트렌드 데이터 기반 제안 건수 / 총 기회 건수` | 목표: 100 개 중 70 개 이상 자동 제안 | 주별 | 시장 분석 API 연동, 마케팅 자동화 |

## 2. 비즈니스 로직 초안

위 지표를 기반으로 KPI 파이프라인이 작동하는 단계별 흐름을 정의합니다. 이는 데이터가 수집되고 분석되어 실제 행동을 유도하는 '폐쇄 루프 (Closed Loop)'를 형성합니다.

1.  **데이터 수집 및 통합**
    - **입력**: 공인중개사 업무용 CRM, 결제 시스템 (PayPal), 시장 트렌드 API (부동산 가격 데이터) 에서 실시간 데이터를 수집합니다.
    - **처리**: 수집된 데이터를 'KPI Metric Table'에 저장하고 이상 징후 (예: 수익성 급감, 응대 지연) 를 감지합니다.

2.  **분석 및 판단**
    - **규칙 기반 분석**: `if GPPD < 목표치 then 가격 재조정 제안`, `if 자동화 처리 시간 > 5 분 then 데이터 파이프라인 병목 해결' 등 비즈니스 로직 규칙을 적용합니다.
    - **예측 모델 연동 (장기)**: LLM 기반 예측 모델을 통해 미래 트렌드 (재개발 수요, 정책 변화) 를 예측하여 사전 대응 전략을 수립합니다.

3.  **행동 유도 및 실행**
    - **자동화 실행**: 분석 결과에 따라 자동화된 행동이 실행됩니다.
      - 예: `GPPD < 목표치` → '가격 재조정 제안' 알림 발송, '마케팅 예산 최적화' 제안 자동 생성.
      - 예: `응대 효율성 낮음` → AI 채팅봇 응답 템플릿 업데이트, '고객 맞춤형 메시지' 자동 작성.

4.  **피드백 및 최적화**
    - 실행 결과 (예: 수익 증가, 고객 만족도 향상) 를 다시 데이터로 수집하여 로직 규칙과 예측 모델의 정확도를 개선합니다.
    - **ROI 평가**: 각 행동의 ROI 를 계산하여 비효율적인 규칙은 제거하고 효율적인 것은 강화합니다.

## 3. 데이터 모델 설계 방향성

KPI 파이프라인을 구현하기 위해 다음 데이터 모델의 핵심 엔티티와 관계를 설계해야 합니다. 이 모델은 '비즈니스 로직'과 '지식 저장소'를 연결하는 기반이 됩니다.

### **핵심 테이블 (Tables)**
- `kpi_metric`
  - **ID**: 고유 식별자 (UUID)
  - **metric_name**: 지표명 (예: GPPD, 자동화 처리 시간 등)
  - **value**: 현재 측정값
  - **threshold**: 목표치 또는 경고 임계값
  - **status**: 정상/경고/위험 상태
- `business_rule`
  - **ID**: 고유 식별자 (UUID)
  - **rule_name**: 규칙명 (예: '수익성 재조정' 규칙)
  - **condition_expression**: 조건식 (예: `GPPD < 30 만원`)
  - **action_type**: 실행 행동 (알림 발송, 예산 조정 등)
- `event_log`
  - **ID**: 고유 식별자
  - **timestamp**: 이벤트 발생 시간
  - **metric_id**: 관련 지표 ID
  - **rule_id**: 적용된 규칙 ID
  - **action_taken**: 실행된 행동 및 결과

### **엔티티 관계 (Relationships)**
- `kpi_metric` ↔ `business_rule`: 특정 지표에 대한 로직 규칙을 매핑합니다. (1:N)
- `event_log` ↔ `metric`, `rule`: 이벤트 발생 시 해당 지표와 규칙의 상태를 기록합니다. (N:M)

### **설계 주의사항**
- **실시간성**: KPI 파이프라인은 실시간 데이터 처리를 요구하므로, 테이블 설계 시 인덱싱과 파티셔닝을 고려해야 합니다.
- **확장성**: 미래에 새로운 지표나 로직이 추가될 경우 모델의 유연성을 확보해야 합니다.
