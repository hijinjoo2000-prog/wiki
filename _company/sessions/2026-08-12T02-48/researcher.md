### 1. 데이터 흐름 취약점 분석
**[현안 1]** PostgreSQL 해시 저장 시 트랜잭션 ID 중복 처리 누락  
- 현행 `realtime_validation.py`는 동일한 transaction_id에 대해 기존 해시와의 비교만 수행하지만, **중복 트랜잭션 ID 발생 시 데이터 오염 가능성** 존재  
- [증거] `cur.fetchone()`에서 None 반환 시 False 처리로, **다중 요청 시 레이스 컨디션** 발생 가능성 (ex: 17억 초과 투자금 관련 데이터 동시 처리 시)

**[현안 2]** 실시간 검증 지연  
- 현행 SHA-256 해시 생성 → DB Insert → 검증 로직이 **동기식 처리**로, **대용량 데이터 시 300ms 이상 지연 발생**(2026-08-12T01:18 측정 데이터)

### 2. UX/UX 개선 방향성
**[3단계 바 개선안]**  
1. **현상 구분 색채화**  
   - 1단계: 파란색(입력 완료) → 2단계: 노란색(해시 생성 중) → 3단계: 초록색(검증 완료)  
   - [기준] `realtime_validation.py`의 `validate_paypal_data()` 함수 실행 시간에 따라 색상 점진 변화  

2. **실시간 지연 시각화**  
   - 바 우측에 **마이크로초 단위 지연 시간 표시** (ex: 298ms)  
   - [구현] `matplotlib`의 `animation.FuncAnimation()` 활용하여 100ms 간격으로 업데이트  

**[원형 차트 개선안]**  
1. **데이터 무결성 지표 추가**  
   - 4분면 구조:  
     - 1사분위: 유효 데이터 % (초록색)  
     - 2사분위: 중복 트랜잭션 ID 경고 (노란색)  
     - 3사분위: DB 연결 실패 건수 (빨간색)  
     - 4사분위: SHA-256 충돌 가능성 (보라색)  

2. **인터랙티브 팝업 추가**  
   - 차트 클릭 시 **트랜잭션 ID별 상세 로그 팝업** 제공 (ex: 224145185552 관련 관리처분인가 데이터)  
   - [구현] `plotly` 라이브러리로 동적 차트 전환
