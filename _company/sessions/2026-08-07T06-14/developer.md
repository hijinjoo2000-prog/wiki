## ⚙️ 시스템 통합 계획: A/B 테스트 및 LLM 실패 방지 연동

### 1. 데이터 로깅 시스템 설계 (A/B Test Data Logging)

목표는 TTC, PCR, CR 데이터를 실시간으로 정확하게 기록하고 추적하는 파이프라인을 구축하는 것입니다.

**아키텍처 제안:**
*   **데이터 수집 레이어 (Collector Layer):** 사용자 인터페이스(UI) 상호작용 및 결제 흐름에서 발생하는 모든 이벤트(시작 시간, 완료 시간, 피드백 점수)를 캡처합니다. (Frontend/Backend Event Tracking)
*   **데이터 저장 레이어 (Storage Layer):** 수집된 데이터를 시계열 데이터베이스(Time-Series DB) 또는 관계형 데이터베이스(SQL)에 저장하여 효율적인 분석을 지원합니다. Parquet 파일로 구조화된 데이터를 보조적으로 저장하여 AI 모델 학습에 활용합니다.
*   **ETL/Pipeline (Processing Layer):** 실시간으로 수집된 원시 데이터에서 TTC, PCR 값을 계산하고 A/B 그룹별 결과를 집계하는 파이프라인을 실행합니다.

**통합 계획:**
1.  **트랜잭션 연동:** 결제 프로세스 시작 시점과 종료 시점에 **고유 세션 ID**를 생성하여 모든 관련 이벤트(TTC 측정, PCR 피드백)에 연결합니다.
2.  **데이터 구조 표준화:** Researcher가 확정한 `price_efficiency_label` 및 A/B 그룹 분류 기준을 데이터베이스 스키마에 강제 적용하여 일관성을 확보합니다. (이것이 D2C 계약의 입력값으로 사용됨)

### 2. LLM 호출 실패 방지 시스템 설계 (Failure Resilience)

LLM 기반의 자동화된 콘텐츠 생성이나 분석 단계에서 발생하는 실패(API 오류, Context Length 초과, 모델 로드 실패 등)를 최소화하고 복구하는 메커니즘을 도입합니다.

**아키텍처 제안:**
*   **Retry Mechanism (재시도 메커니즘):** API 호출 실패 시 즉시 재시도를 수행하며, 실패 횟수에 따라 지수 백오프(Exponential Backoff) 전략을 적용하여 서버 부하를 관리합니다.
*   **Fallback Strategy (대체 전략):** 주 모델(예: Gemini) 호출이 실패할 경우, 사전에 정의된 대체 모델(예: 다른 LLM 또는 경량화된 모델)로 자동 전환하여 작업을 지속합니다.
*   **Context Management (컨텍스트 관리):** `AI_City_Master_Plan`의 구조를 활용하여, 각 단계별로 필요한 정보만 프롬프트에 주입하고 Context Length 초과를 사전에 모니터링하여 입력 길이를 동적으로 조정합니다.

**통합 계획:**
1.  **데이터 의존성 관리:** LLM이 데이터를 요청할 때, 데이터 파이프라인(Section 1)의 상태를 먼저 확인하도록 로직을 구성합니다. 만약 데이터 수집 단계에서 오류가 발생하면, LLM 호출은 **실패 대신 데이터 불완전 경고**를 반환하고 시스템에 실패 원인을 보고하도록 합니다.
2.  **D2C 계약 반영:** 'Design-to-Code Contract' 내에 **'Error Handling & Fallback Specification'** 섹션을 추가하여, 어떤 종류의 API/LLM 오류가 발생했을 때 시스템이 취해야 할 구체적인 행동(재시도, 대체 모델 사용, 사용자에게 알림)을 명문화합니다.

### 3. Design-to-Code Contract (D2C) 프레임워크 통합 계획

기존의 D2C 계약(`developer.md`, `dashboard-kit` 등)에 위에서 정의한 시스템 요구사항을 **입력 변수 및 검증 규칙**으로 통합합니다.

| 기존 D2C 요소 | 통합할 내용 (신규 요구사항) | 목적 |
| :--- | :--- | :--- |
| **데이터 입력 명세** | A/B 테스트 결과(TTC, PCR, CR)의 필수 로깅 필드 정의 및 스키마 강제화. | 측정된 인지 부하가 코드로 반영되도록 보장. |
| **프레임워크 구조** | LLM 호출 실패 시점별 **Rollback & Recovery Flowchart** 삽입. | 시스템 안정성 확보 및 자동 복구 로직 정의. |
| **코드 생성 규칙** | 모든 백엔드 로직에 **Input Validation Gate**를 의무화하고, 데이터 소스(DB/API)의 유효성을 검증하도록 코딩 규칙을 강화. | 잘못된 입력으로 인한 시스템 오류 방지. |
