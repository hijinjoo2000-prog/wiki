## 🔍 식별된 핵심 기술적 병목 지점 (Top 3 Bottlenecks) 및 해결 방안

### 1. 병목: 데이터 파이프라인의 End-to-End 무결성 확보
**문제 정의:** 네이버 부동산 및 MLS 데이터 수집부터 최종 Parquet 파일 저장까지의 과정에서 발생하는 데이터 손실, 변형(Corruption), 또는 누락 위험. 이는 A/B 테스트 결과와 최종 KPI 산출의 근본적인 신뢰도를 훼손합니다.

**해결 방안 (Solution):**
*   **구체적 액션:** `data_pipeline.py` 내에서 모든 I/O 및 변환 단계에 대한 **체크포인트 로깅(Checkpoint Logging)** 메커니즘을 구현합니다. 각 파이프라인 단계(수집 $\rightarrow$ 정제 $\rightarrow$ 레이블링 $\rightarrow$ 저장)가 성공적으로 완료되었는지 확인하는 상태 플래그를 데이터 레코드에 삽입하고, 실패 시 즉시 알림을 발생시키는 **Fail-Fast 전략**을 적용합니다.
*   **기술 검증:** 파이프라인 실행 후, 출력된 Parquet 파일의 전체 행 수를 원본 수집 데이터와 비교하여 100% 일치하는지 자동 검증 로직을 추가합니다.

### 2. 병목: LLM 실패 방지 메커니즘 (FTRC 연동)의 실시간 신뢰성
**문제 정의:** AI 가치 평가 모델 학습 과정에서 발생하는 LLM 오류나 비정상적인 출력을 탐지하고 이를 차단하는 FTRC(Failure-Tolerant Reasoning Chain) 메커니즘이 실제 운영 환경(실시간 데이터 흐름)에서 일관되게 작동하고 그 결과를 신뢰하기 어렵습니다.

**해결 방안 (Solution):**
*   **구체적 액션:** LLM 추론 요청 시, 단순 성공/실패 외에 **'신뢰도 점수(Confidence Score)'**를 반드시 반환하도록 모델 인터페이스를 수정하고, 이 점수가 특정 임계값 이하일 경우 자동으로 데이터를 보류(Quarantine)하는 로직을 강화합니다.
*   **기술 검증:** 데이터 수집 단계에서 발생하는 모든 LLM 관련 오류 로그와 FTRC의 차단 기록을 **별도의 안정적인 데이터 스토리지**에 분리하여 저장하고, 이 로그를 실시간으로 모니터링할 수 있는 별도의 대시보드 연결을 구축합니다.

### 3. 병목: 측정 인프라 (A/B 테스트 로깅)의 정확성 및 지연 시간 최소화
**문제 정의:** 공인중개사 결제 전환율($\Delta$CL, PCR 등)과 같은 핵심 KPI를 측정하기 위한 데이터 수집 시스템이 실시간으로 작동하지 않거나, 로깅 과정에서 발생하는 지연(Latency)으로 인해 실제 성과와 측정값 사이에 괴리가 발생할 위험.

**해결 방안 (Solution):**
*   **구체적 액션:** 데이터 수집 및 이벤트 발생 시점의 **타임스탬프(Timestamp)**를 서버 측(Backend)에서 생성하고, 클라이언트 측(Frontend) 전송 직후와 DB 저장 직전에 이중으로 타임스탬프를 기록하여 측정값의 시간적 정확성(Temporal Accuracy)을 확보합니다.
*   **기술 검증:** 데이터베이스에 최종 로깅된 이벤트와 API 호출 로그 간의 지연 시간을 주기적으로 측정하는 **Latency Monitoring Agent**를 도입하고, 이 지연 시간이 허용 오차 범위 내에 있는지 자동으로 알림을 설정합니다.
